# ツール呼び出しの上限に達したときのまとめ（`llm.on_tool_call_limit`）

ツールループの往復回数が上限（`llm.max_tool_call_iterations`。定期タスクでは YAML の
`max_tool_call_iterations`）に達すると、処理はそこで止まります。このときに何を返すかを
`llm.on_tool_call_limit` で選べます。

```yaml
llm:
  max_tool_call_iterations: 10
  on_tool_call_limit: summarize   # 既定。message にすると従来の固定文言だけを返す
```

| 値 | 動作 |
|----|------|
| `summarize`（**既定**） | ツールなしで LLM を 1 回だけ呼び、ここまでの結果をまとめさせてその本文を返す |
| `message` | ロケールの固定文言（`conversation.tool_call_limit`。`llm_expert` の中では `tool.llm_expert.tool_call_limit`）だけを返す（以前の挙動） |

それ以外の値を書くと起動時に失敗します。

## `summarize` の動作

- 上限に達した時点のメッセージ列（会話履歴・ツール呼び出し・ツール結果）の末尾に、
  まとめの指示を user メッセージとして足し、**ツールを渡さずに 1 回だけ** LLM を呼びます。
  指示はコード内の固定の英文で、次の内容を求めます。
  - ツール呼び出しの上限に達して途中で止めたこと、これ以上ツールは使えないこと
  - 応答の冒頭で、上限に達して途中で止まったことを必ずユーザーに伝えること
  - ここまでに分かったこと・できたこと・まだできていないことを分けて、システムプロンプトの
    普段の口調・会話と同じ言語で簡潔にまとめること
  - 終わっていない作業を「完了した」と書かないこと、ツール結果の事実を変えないこと
  - 続きを依頼してもらえば再開できる旨を添えること
- まとめの本文の後ろに固定文言は付けません。打ち切ったことの伝達は LLM の応答に任せます。
- META ブロック（`set_session_memory` など）の適用と再認証の案内の付け足しは、通常の
  最終応答と同じに行います。定期タスク（`task_scheduled_llm`）でまとめが `NO_NOTIFICATION`
  を返した場合も、通常の返答と同じく通知しません。
- まとめの呼び出しが失敗したとき、または応答が空のときは、WARNING ログを出して `message`
  と同じ固定文言を返します（例外にはしません）。ただし
  [LLM 送信前の拒否リスト](llm-send-guard.md) で送信を止めた場合は、通常の LLM 呼び出しと
  同じ扱いです。

## まとめを書くプロバイダー

- 通常の会話（`run_conversation`）では、最後のループで使った具体プロバイダーが書きます。
  そのプロバイダーに [`final_reply_provider`](llm-final-reply.md) があれば、まとめは最終応答に
  あたるため指定先が書きます。指定先の `final_reply_provider` は見ません。
- `final_reply_provider` による書き直しの途中で上限に達したときは、書き直し先がそのまま
  まとめを書きます（書き直しを重ねません）。
- `llm_expert` の内側のループで上限に達したときも同じくまとめを返しますが、書くのは専門家の
  `llm_provider` です（専門家の応答はユーザーへの最終応答ではないため、`final_reply_provider`
  は見ません）。

## 注意

- 上限に達した回は LLM の呼び出しが 1 回増えます（ツールなしの 1 回だけです）。使用量の
  記録（[LLM のトークン使用量の記録](llm-usage.md)）にも 1 件残ります。
- 固定文言を付けないため、LLM が打ち切りに触れない・未完了の作業を完了と書く可能性は
  残ります。気になる場合は `message` に戻してください。
