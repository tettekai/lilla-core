# 拡張のタスクの上書き

拡張が同梱する定期タスク（`tool_config_roots()` で同梱した `task_*.yaml`）の実行スケジュール
（crontab）と有効・無効を、拡張のコードやツール YAML を編集せずに、MongoDB のドキュメント 1 件で
拡張ごとに上書きできます。上書きは [拡張のデフォルトプロンプトと上書き](extension-prompt.md) と
同じ `extension_overrides` コレクションの、拡張ごとのドキュメントに書きます。

## 上書きドキュメント

拡張ごとのドキュメントに、トップレベルのキー `tasks` を足します。キーはタスクのツール名
（YAML のファイル名 stem。スケジューラのジョブ ID と同じ）です。

```json
{
  "extension": "diary",
  "prompt": "（任意。プロンプトの上書き）",
  "tasks": {
    "task_diary_digest": { "schedule": "30 21 * * *" },
    "task_diary_cleanup": { "enabled": false }
  },
  "updated_at": { "$date": "2026-10-28T00:00:00Z" }
}
```

```javascript
db.extension_overrides.updateOne(
  { extension: "diary" },
  { $set: { "tasks.task_diary_digest.schedule": "30 21 * * *", updated_at: new Date() } },
  { upsert: true },
)
```

書き込みの API と、ダッシュボードの編集画面はまだありません。`mongosh` などで直接入れます。

## 上書きできる項目

| 項目 | 型 | 意味 |
|------|----|------|
| `schedule` | 文字列（crontab） | 実行スケジュール。既存と同じく `ui.timezone`（未指定なら OS のローカル）で解釈する |
| `enabled` | 真偽値 | `false` ならスケジューラにジョブを登録しない |

- 項目ごとに上書きします。書いていない項目はデフォルト（ツールの `schedule`、有効）を使います。
- `tasks` キーの無いドキュメント、ドキュメントの無い拡張は、全タスクがデフォルトです。
- `tasks` の有無や中身は、`prompt` の上書きに影響しません（逆も同じ）。
- タスクの内容やタスク用のプロンプトは上書きできません。ツール YAML・タスクの実装に書きます。

## 対象になるタスク

- 上書きできるのは、その拡張が `tool_config_roots()` で同梱したタスクだけです。
- 利用者が `${CONFIG_ROOT}/tools` に同じ stem の YAML を置いて同梱分を置き換えている場合も、
  そのタスクはその拡張のものとして扱います。置き換え後の YAML の内容をデフォルトとみなし、
  その上に上書きを重ねます。
- 拡張に属さないタスク（コア組み込みのタスクや、利用者だけが置いた YAML のタスク）は対象外です。
  スケジュールは利用者の YAML で決めます。

## `enabled` の違い

ツール YAML の `enabled: false` と、上書きの `enabled: false` は意味が異なります。

| 書く場所 | 意味 | `!runtask` での手動実行 |
|----------|------|------|
| ツール YAML の `enabled: false` | そのツールを **ロードしない** | できない |
| 上書きの `enabled: false` | ツールはロードしたまま、**定期実行のジョブを登録しない** | できる |

YAML で `enabled: false` にしてロードしていないタスクは、上書きで `enabled: true` としても
有効になりません（WARNING を出して無視します）。

## 不正な値の扱い

次の場合は、拡張名とツール名を含む WARNING ログを出し、そのタスク（またはその項目）を
デフォルトにします。起動は止めません。

- `tasks` がオブジェクトでない
- タスクごとの値がオブジェクトでない
- `schedule` が文字列でない、または crontab として解釈できない
- `enabled` が真偽値でない
- 拡張が同梱していない（またはロードされていない・スケジュールを持たない）ツール名が書かれている

MongoDB からの読み込み自体に失敗した場合は、WARNING ログを出して全タスクをデフォルトで登録します。

## 反映のタイミング

上書きは起動時（Discord への接続完了時にスケジューラを起こすとき）に読みます。キャッシュは
しません。

**現時点では、本番で上書きを変えたら再起動が必要です。** 稼働中のスケジューラへ再起動なしで
反映する非同期のメソッド `lilla_core.handlers.task_handler.apply_task_overrides(extension_name,
task_name=None)` はありますが、本番のコードから呼ぶ箇所はまだありません（ダッシュボードの編集画面が
上書きを書き込んだあとに呼ぶ予定です）。変更の監視やポーリングはしません。

- 起動時の登録も同じ適用処理を通ります。
- 反映では、スケジュールが変われば差し替え、`enabled: false` ならジョブを外し、ジョブが無いのに
  有効ならデフォルトのジョブ関数で登録し直します。上書きを消して反映すると、デフォルトに戻ります。
- 実行中のジョブは止めません。差し替えは次回以降の実行に効きます。
- 反映時に読み込みに失敗した場合も、起動時と同じくその拡張のタスクをデフォルトに戻します。

上書きが効いたかは、起動時と反映時に出る INFO ログ `[TASK] Next run of <ツール名>: <次回実行時刻>`
で確かめられます。

## 注意点

- **ツール名と拡張の `name` が上書きの識別子です。** 拡張側でツール名（YAML の stem）や
  `Extension.name` を変えると、既存の上書きは効かなくなります。
- 上書きしていない項目は、拡張のデフォルトに追随します。
