# 拡張のデフォルトプロンプトと上書き

拡張は、自分が前提とするプロンプトをコードの中にデフォルトとして持てます。
`LILLA_EXTENSIONS` で有効にするだけでそのプロンプトがシステムプロンプトに入るため、
利用者が `prompt.system` のファイルを書き足す必要はありません。利用者はコードや
ファイルを編集せずに、MongoDB のドキュメント 1 件で拡張ごとに本文を上書きできます。

## デフォルトプロンプトの書き方

`Extension.default_prompt()` をオーバーライドし、言語ごとの本文を返します。

```python
from lilla_core.core.extension import Extension


class DiaryExtension(Extension):
    name = "diary"

    def default_prompt(self):
        return {
            "ja": "## 日記\n会話の終わりに、その日の出来事を一言で振り返ってください。",
            "en": "## Diary\nAt the end of a conversation, reflect on the day in one line.",
        }


extension = DiaryExtension()
```

- 戻り値は `{"言語": "本文"}` の `dict` です。既定は `None`（プロンプトを持たない）。
- 特定の言語は必須ではありません（英語だけの拡張も書けます）。利用者の `ui.locale` に
  合わせられるよう、できるだけ `ja` と `en` の両方を用意してください（一方から翻訳したもので
  かまいません）。
- 1 つの拡張が持てるプロンプトは 1 つだけです。
- 形はロード時に検証します。`dict` でない・空の `dict`・キーや値が文字列でない場合は、
  起動時に `ValueError` で失敗します。
- `client_prompt_providers()` と違い、`client_type` によらずすべての会話に入ります
  （`task` を除く。[下記](#挿入位置)）。

## 上書きドキュメント

上書きは MongoDB の `extension_overrides` コレクションに、拡張ごとに 1 ドキュメントで
置きます。上書きしたい拡張のぶんだけ作り、無ければデフォルトを使います。

```json
{
  "extension": "diary",
  "prompt": "上書きするプロンプト本文",
  "updated_at": { "$date": "2026-10-27T00:00:00Z" }
}
```

- `extension` には拡張の `name` を書きます（ユニークインデックスがあり、起動時に作られます）。
- `prompt` は言語の区別を持たない文字列 1 つで、デフォルトの全文を置き換えます。
- `prompt` に空文字を書くと、「その拡張のプロンプトを注入しない」という上書きになります。
- ドキュメントがあっても `prompt` キーが無ければ、デフォルトを使います（同じドキュメントの
  `tasks` キーでタスクのスケジュールも上書きできます。[拡張のタスクの上書き](extension-task-override.md)。
  今後 `settings` などのキーも足す予定で、存在するキーだけが上書きになります）。
- `prompt` が文字列でない（数値・配列・オブジェクト・`null` など）場合は、拡張名を含む
  WARNING ログを出してデフォルトを使います。
- 書き込みの API と、ダッシュボードの編集画面はまだありません。`mongosh` などで直接入れます。

```javascript
db.extension_overrides.updateOne(
  { extension: "diary" },
  { $set: { prompt: "上書きするプロンプト本文", updated_at: new Date() } },
  { upsert: true },
)
```

上書きはキャッシュせず、システムプロンプトを組み立てるたびに読みます。再起動しなくても
次の応答から効きます。

## 本文の決め方

デフォルトプロンプトを持つロード済みの拡張ごとに、次の順で本文を決めます。

1. 上書きドキュメントに `prompt` キーがあり、値が文字列ならそれを使う
2. 無ければ、`ui.locale` に一致する言語のデフォルトを使う
3. `ui.locale` に一致するデフォルトが無ければ、`ja` → `en` → 定義の先頭の言語の順に、
   最初に見つかったものを使う

上書きの読み込み自体に失敗した場合（MongoDB に届かないなど）は、WARNING ログを出して
すべての拡張をデフォルトで注入します。応答は止めません。

## 挿入位置

決めた本文を `LILLA_EXTENSIONS` の並び順で空行区切りに連結し、次の位置へ入れます。
既存のシステムプロンプトを置き換えるものではなく、追加で重ねるものです。

```
（共通のシステムプロンプト: prompt.system）
（client_type ごとの追記: prompt.discord や client_prompt_providers()）
（会話プロンプト: prompt.conversation）
（拡張のプロンプト）            ← ここ
（登録チャンネルの一節）
（部屋のノート・ユーザーメモ・セッションメモリ・現在時刻など）
```

会話プロンプトと同じく、`client_type` が `task`（定期タスク）のときは注入しません。

## 注意点

- **上書きは言語を区別しません。** 上書きしたあとに `ui.locale` を変えても、上書きした本文は
  切り替わりません。言語を変えたら上書きを入れ直してください。
- **上書きした拡張は、デフォルトの更新に追随しません。** 拡張のバージョンアップでデフォルトが
  変わっても、上書きした本文のままです。上書きしていない拡張は、常に最新のデフォルトを使います。
- **拡張の `name` が上書きドキュメントの識別子です。** 拡張の `name` を後から変えると、
  既存の上書きは効かなくなります。
- 応答のたびに MongoDB を 1 回多く読みます（デフォルトプロンプトを持つ拡張が 1 つも
  なければ読みません）。
