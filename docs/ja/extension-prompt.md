# 拡張のデフォルトプロンプトと上書き

拡張は、自分が前提とするプロンプトをコードの中にデフォルトとして持てます。
`LILLA_EXTENSIONS` で有効にするだけでそのプロンプトがシステムプロンプトに入るため、
利用者が `prompt.system` のファイルを書き足す必要はありません。利用者はコードや
ファイルを編集せずに、MongoDB のドキュメント 1 件で拡張ごとに本文を上書きできます。

## デフォルトプロンプトの書き方

`Extension.default_prompt()` をオーバーライドし、言語ごとの本文を返します。

```python
from lilla_core.core.extension import Extension


class DiaryExtension(Extension):
    name = "diary"

    def default_prompt(self):
        return {
            "ja": "## 日記\n会話の終わりに、その日の出来事を一言で振り返ってください。",
            "en": "## Diary\nAt the end of a conversation, reflect on the day in one line.",
        }


extension = DiaryExtension()
```

- 戻り値は `{"言語": "本文"}` の `dict` です。既定は `None`（プロンプトを持たない）。
- 特定の言語は必須ではありません（英語だけの拡張も書けます）。利用者の `ui.locale` に
  合わせられるよう、できるだけ `ja` と `en` の両方を用意してください（一方から翻訳したもので
  かまいません）。
- 1 つの拡張が持てるプロンプトは 1 つだけです。
- 形はロード時に検証します。`dict` でない・空の `dict`・キーや値が文字列でない場合は、
  起動時に `ValueError` で失敗します。
- `client_prompt_providers()` と違い、`client_type` によらずすべての会話に入ります
  （`task` を除く。[下記](#挿入位置)）。

## 上書きドキュメント

上書きは MongoDB の `extension_overrides` コレクションに、拡張ごとに 1 ドキュメントで
置きます。上書きしたい拡張のぶんだけ作り、無ければデフォルトを使います。

```json
{
  "extension": "diary",
  "prompt": { "mode": "append", "text": "デフォルトの後ろに書き足す本文" },
  "updated_at": { "$date": "2026-10-27T00:00:00Z" }
}
```

- `extension` には拡張の `name` を書きます（ユニークインデックスがあり、起動時に作られます）。
- `prompt` は `mode` と `text` の 2 つのキーだけを持つオブジェクトです。モードと本文は 1 つの
  フィールドとしていっしょに保存し、デフォルトと合わせた全文は保存しません。
  - `mode: "append"`（デフォルトプロンプトに追加）: デフォルトの本文の後ろに `text` を空行区切りで
    書き足します。デフォルトの部分は実行時点のものを使うため、拡張のデフォルトが更新されたり
    `ui.locale` を変えたりしても追従します。`text` が空ならデフォルトだけになります。
  - `mode: "replace"`（デフォルトプロンプトを置き換える）: `text` だけを使います。`text` に空文字を
    書くと、「その拡張のプロンプトを注入しない」という上書きになります。
  - `text` は言語の区別を持たない文字列です（翻訳はされません）。
- ドキュメントがあっても `prompt` キーが無ければ、デフォルトを使います（同じドキュメントの
  `tasks` キーでタスクのスケジュールも上書きできます。[拡張のタスクの上書き](extension-task-override.md)。
  今後 `settings` などのキーも足す予定で、存在するキーだけが上書きになります）。
- `prompt` がこの形に合わない（文字列・数値・`null`・キーの過不足・未知の `mode`・`text` が
  文字列でないなど）場合は、拡張名を含む WARNING ログを出してデフォルトを使います。
  不正な本文は注入しません。
  - 以前の形式（`prompt` が文字列 1 つで全文を置き換える形）は読み替えず、この「不正」として
    扱います。残っている場合は、Extensions 画面で上書きを保存し直すか「デフォルトに戻す」を
    押してください（自動では移行しません）。
- ふだんは観測用ダッシュボードの **Extensions** 画面（管理メニュー、`#/admin/extensions`）で
  編集します（[観測用ダッシュボード](dashboard.md#extensions)）。「デフォルトに戻す」は `prompt`
  キーを消すだけで、デフォルトの本文を上書きとしてコピーしません。下の例のように `mongosh`
  などで直接入れることもできます。

```javascript
db.extension_overrides.updateOne(
  { extension: "diary" },
  { $set: { prompt: { mode: "append", text: "書き足す本文" }, updated_at: new Date() } },
  { upsert: true },
)
```

上書きはキャッシュせず、システムプロンプトを組み立てるたびに読みます。再起動しなくても
次の応答から効きます。

## 本文の決め方

デフォルトプロンプトを持つロード済みの拡張ごとに、次のように本文を決めます。

1. その拡張自身の `default_prompt()` から、`ui.locale` に一致する言語のデフォルトを選ぶ。
   無ければ `ja` → `en` → 定義の先頭の言語の順に、最初に見つかったものを使う
   （共通のシステムプロンプトや、ほかの拡張の本文は対象にしません）
2. 上書きが無ければ、デフォルトだけを使う
3. `append` なら、デフォルトと `text` を **それぞれ独立した**
   [テンプレート](#テンプレートで設定値を埋め込む) として展開し、展開した結果をこの順に
   空行（`\n\n`）区切りでつなぐ
4. `replace` なら、`text` だけを展開して使う

- つないだ本文を 1 つのテンプレートとして展開することはしません。そのため、追加分（`text`）から
  デフォルト側の `{% set %}` やマクロは参照できません（逆も同じです）。どちらからも使えるのは、
  共通の `current_hour` と、その拡張の `settings` だけです。
- 空または空白だけの部分は展開しません。展開した結果が空白だけになった部分もつながず、
  余分な区切りを足しません。両方とも空白だけなら、その拡張のプロンプトは注入しません。
- 展開に失敗した部分は、展開前の本文をそのまま使います（下記）。もう一方の部分の展開結果には
  影響しません。

上書きの読み込み自体に失敗した場合（MongoDB に届かないなど）は、WARNING ログを出して
すべての拡張をデフォルトで注入します。応答は止めません。

## テンプレートで設定値を埋め込む

デフォルトプロンプトも上書きも、[Jinja2](https://jinja.palletsprojects.com/) の
テンプレートとして展開してから注入します。拡張の画面管理の設定
（`settings_model()`。[画面管理の拡張設定](extension-settings.md)）の値を、プロンプトに
埋め込めます。

```python
    def default_prompt(self):
        return {
            "ja": (
                "## 日記\n"
                "{% if settings.faircopy_storage %}"
                "清書は notes の `diary/{{ settings.faircopy_path }}` に保存されます。"
                "{% else %}"
                "清書は自動では保存されません。"
                "{% endif %}"
            ),
        }
```

- テンプレートに渡す変数は、どのプロンプトにも共通の `current_hour`（[プロンプトのテンプレート](prompt-template.md)）と、
  拡張のプロンプトだけの `settings` です。`settings` の中身はその拡張の設定を、システムプロンプトを
  組み立てるたびに読み直したものです（保存した値は次の応答から効きます）。設定を持たない
  拡張では `settings` は空で、DB も読みません。
- `SecretStr` / `SecretBytes` の型の項目は `settings` に入りません（入れ子のモデルやリストの
  中にある値も除きます）。
- 使えるのは Jinja2 の通常の構文（`{{ settings.名前 }}`・`{% if %}`・`{% for %}`・フィルター
  など）です。展開はサンドボックスで行い、テンプレートから Python の属性やモジュールへは
  届きません。HTML ではないため自動エスケープはしません。
- 設定値は展開済みの値としてそのまま出力し、値の中の `{{` はもう一度展開しません。
- `settings` は読み取り専用の入れ物で、`settings.名前` と `settings['名前']` はどちらも項目の値を
  返します。項目名が `items` / `keys` / `get` などと同じでも値になります（入れ子の設定・リストの中も同じ）。
- 未定義の名前（綴り間違いなど）は空文字にせず失敗にします。
- 展開に失敗した場合（構文エラー・未定義の名前・サンドボックスの拒否など）は、拡張名を含む
  WARNING ログを出し、その部分（デフォルトか追加分）は **展開前の本文をそのまま** 注入します。
  応答は止めません。設定を読めないときは、デフォルトも追加分も展開前の本文を使います。
  成功したときはログを出しません。
- 展開後の本文が空白だけなら、その拡張のプロンプトは注入しません。
- 本文の末尾の改行は残します（記法を含まない本文は展開しても変わりません）。
- `{{` / `{%` / `{#` を文字として書きたいときは、`{% raw %}…{% endraw %}` で囲みます。

### 拡張の作者が気をつけること

- 既存のデフォルトプロンプトに `{{` / `{%` / `{#` が文字として含まれていると、展開に失敗して
  WARNING が出続けます。`{% raw %}` で囲むか、書き方を変えてください。
- `notes_directories()` の用途の文は notes のデフォルトプロンプトの一部として展開されるため、
  `{{` / `{%` / `{#` を書かないでください（コアは検査もエスケープもしません）。

### ダッシュボードでの上書き

Extensions 画面で上書きを保存するときは、`append` / `replace` のどちらでも **入力した本文（`text`）
だけ** の構文を確かめ、そのうえで今の設定で試しに展開します。デフォルトとつないだ本文は
確かめません（デフォルトにだけ問題があっても、入力した本文が正しければ保存できます）。
構文エラー・未定義の名前・サンドボックスの拒否は 400 になり、保存しません。実行時も追加分は
独立して展開するため、この試しの展開の結果は実行時の追加分の展開結果と一致します。

- 試しの展開で確かめられるのは、今の設定で通る分岐だけです（`{% if %}` の通らない側にある
  綴り間違いは見つかりません）。保存後に設定を変えて別の分岐へ入ったとき、展開に失敗すると
  上と同じく展開前の本文が注入されます。
- 設定を読めない（DB に届かない・保存値が不正）ときは、試しの展開を飛ばして構文だけを
  確かめます。
- 画面では「デフォルトプロンプトに追加」と「デフォルトプロンプトを置き換える」を選び、
  追加モードのときだけ入力欄の上にデフォルトの本文（言語つき・読み取り専用）が出ます。
  モードを切り替えても入力した本文は消えず、デフォルトが自動で差し込まれることもありません。
  デフォルトを編集のベースにしたいときは、追加モードの表示からコピーし、置き換えモードで
  貼り付けます。入力欄には保存済みのモードと本文が入り、デフォルトと合わせた全文は入りません。
- 入力欄は [Jinja2 テンプレートの入力欄](dashboard.md#jinja2-テンプレートの入力欄) で、`current_hour` と
  `settings.名前` で使える名前（秘匿値の項目は除く）をクリックで差し込めます。入力中は保存時と
  同じ試しの展開を行い、入力した本文だけの展開後のプレビュー（今の設定と今の時刻で展開したもの）と
  エラーの理由を出します。
  通らない分岐の中を確かめられないのは保存時と同じです。

## 挿入位置

決めた本文を `LILLA_EXTENSIONS` の並び順で空行区切りに連結し、次の位置へ入れます。
既存のシステムプロンプトを置き換えるものではなく、追加で重ねるものです。

```
（共通のシステムプロンプト: prompt.system）
（client_type ごとの追記: prompt.discord や client_prompt_providers()）
（会話プロンプト: prompt.conversation）
（拡張のプロンプト）            ← ここ
（登録チャンネルの一節）
（部屋のノート・ユーザーメモ・セッションメモリ・現在時刻など）
```

会話プロンプトと同じく、`client_type` が `task`（定期タスク）のときは注入しません。

## 注意点

- **上書きの本文は言語を区別しません。** `ui.locale` を変えると、`append` のデフォルト部分は
  新しい言語に切り替わりますが、入力した本文は翻訳されません。`replace` の本文は切り替わりません。
- **`replace` の上書きは、デフォルトの更新に追随しません。** 拡張のバージョンアップでデフォルトが
  変わっても、入力した本文のままです。`append` と、上書きしていない拡張は、常に最新の
  デフォルトを使います。
- **拡張の `name` が上書きドキュメントの識別子です。** 拡張の `name` を後から変えると、
  既存の上書きは効かなくなります。
- 応答のたびに MongoDB を 1 回多く読みます（デフォルトプロンプトを持つ拡張が 1 つも
  なければ読みません）。
