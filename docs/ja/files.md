# ローカルのファイル読み書き（公式拡張パック）

公式拡張パックの `files` 拡張は、LLM がローカルのファイルシステム上のテキストファイルを
一覧・読み取り・書き込み・検索できるようにします。対象は `lilla.yaml` でホワイトリストに
入れたディレクトリの配下だけです。設定やエラーの考え方は
[Google Drive の拡張](google.md) にそろえています。

| import パス | `name` | 役割 |
|-------------|--------|------|
| `lilla_core.extensions.files` | `files` | ホワイトリストのディレクトリ配下のテキストファイル（UTF-8）の一覧・読み取り・書き込み・検索の LLM ツール。他の拡張には依存しない |

## 有効化

```bash
export LILLA_EXTENSIONS=files
# フルパスでも同じ: export LILLA_EXTENSIONS=lilla_core.extensions.files
```

他の拡張と並べる場合も順序の制約はありません。

## 設定

```yaml
extensions:
  files:
    # 読み取りだけを許すディレクトリ。
    read_only_dirs:
      - /srv/lilla/docs
      # UNC パスやマウント先も、OS がそのまま開けるパスならそのまま書ける。
      # - '\\nas\share\manuals'
    # 読み取りと書き込みを許すディレクトリ。
    writable_dirs:
      - /srv/lilla/notes
      # LLM から指すときの名前（既定はパスの末尾の要素）を変えたいときは辞書で書く。
      - path: /home/me/Documents/lilla
        name: mydocs
    # file_read で一度に返す最大の文字数（既定 100000）。
    max_read_chars: 100000
```

| 設定 | 内容 |
|------|------|
| `extensions.files.read_only_dirs` | 読み取りだけを許すディレクトリのリスト（既定は空） |
| `extensions.files.writable_dirs` | 読み取りと書き込みを許すディレクトリのリスト（既定は空） |
| `extensions.files.max_read_chars` | `llm_file_read` で一度に返す最大の文字数（既定 `100000`） |

- 各要素はパスの文字列か、`path` と `name` を持つ辞書で書きます。パスは絶対パスで書きます
  （相対パス・空文字・`smb://` などの URL 形式は起動時に落ちます）。パスが今あるかどうかは
  起動時には確かめません（後からマウントされるディレクトリでも構いません）
- 両方とも空なら、ツールはすべてのアクセスを拒否します（起動はします）
- 同じディレクトリを両方に書くと起動時に落ちます
- ディレクトリの中に別のホワイトリストのディレクトリを入れ子にできます。許す操作は、
  対象を含む最も深いディレクトリで決まります（`writable_dirs` の中に `read_only_dirs` の
  ディレクトリを置けば、その配下は読み取り専用になります）
- 拡張をロードしていないのに節が残っていると、コアは払い残しとして起動時に落とします

### LLM とやりとりするパス

ツールの `path` は **「ディレクトリの名前/その中の相対パス」** の形です（例: `notes/2026/todo.md`）。
名前は `name` を書けばその値、書かなければパスの末尾の要素（`/srv/lilla/notes` なら `notes`）です。
名前が重なると起動時に落ちるので、そのときは `name` で区別してください。末尾の要素が無いパス
（`/` など）にも `name` が必要です。

- 区切りは `/` と `\` のどちらでも受け付け、返すパスは `/` 区切りにそろえます
- `llm_file_list` に空文字を渡すと、アクセスできるディレクトリ（名前）の一覧を返します
- ツールが返す `path` はそのまま他のツールに渡せます

## ツール

ツール本体は `files` 拡張の中にあり、YAML は利用者の `${CONFIG_ROOT}/tools/` に置きます
（拡張は YAML を同梱しません）。使うものだけ置けば十分です（読み取りだけにしたいなら
`llm_file_write.yaml` を置かなければ、書き込みのツールは LLM に見えません）。

```yaml
# ${CONFIG_ROOT}/tools/llm_file_list.yaml
type: llm_file_list
```

```yaml
# ${CONFIG_ROOT}/tools/llm_file_read.yaml
type: llm_file_read
```

```yaml
# ${CONFIG_ROOT}/tools/llm_file_write.yaml
type: llm_file_write
```

```yaml
# ${CONFIG_ROOT}/tools/llm_file_search.yaml
type: llm_file_search
```

| ツール | 内容 |
|--------|------|
| `llm_file_list` | `path` の直下のエントリを名前順に返す（再帰しない）。各要素は `path` / `name` / `type`（`file` / `dir`）/ `size`（ファイルのみ）/ `modified_time`（UTC）/ `writable`。`pattern`（グロブ。例 `*.md`）で名前を絞り込める。500 件を超えたら切り詰めて `truncated: true` |
| `llm_file_read` | UTF-8 のテキストを返す（先頭の BOM は取り除く）。`offset`（文字数。既定 0）と `limit`（既定・上限は `max_read_chars`）で途中から読める。続きがあれば `truncated: true` と `next_offset` を返す。先頭 8KB に NUL バイトがある・UTF-8 として読めない（Shift_JIS など）ファイルは中身を返さず「テキストとして読めない」旨のエラーにする。50MB を超えるファイルは読まない |
| `llm_file_write` | `writable_dirs` の配下だけに、`content` を UTF-8（BOM 無し）で書く（改行コードは変換しない）。`mode` は `create`（既にあれば失敗）/ `overwrite`（丸ごと上書き。無ければ作る）/ `append`（末尾に追記。無ければ作る）。親ディレクトリが無ければ作る。結果の `created` で新しく作ったかがわかる |
| `llm_file_search` | `path`（ディレクトリかファイル。空文字ですべて）の配下のテキストファイルから、`query` を含む行を探して `path` / `line`（行番号）/ `text` を返す（大文字小文字は区別しない）。バイナリ・UTF-8 で読めない・5MB を超えるファイルは黙って飛ばす。該当行 50 件・読むファイル 2,000 件を超えたら切り詰めて `truncated: true` |

## 安全性

- `..`・絶対パス・ドライブ名・NUL を含むパスは受け付けません
- 判定は実体パス（シンボリックリンクを辿った後のパス）で行い、先頭の名前で選んだ
  ディレクトリの外を指すアクセスは拒否します（配下のシンボリックリンクで外へ出る経路も、
  別のホワイトリストのディレクトリへ出る経路も拒否します）。`llm_file_list` は外を指す
  エントリを一覧に出さず、`llm_file_search` は外を指すファイルを読まずディレクトリへの
  リンクを辿りません
- 読み取り専用のディレクトリへの書き込み（入れ子の読み取り専用ディレクトリを含む）は拒否します
- 想定外の例外（ディスクの空き不足など）は、例外の文字列を LLM へ返さず汎用の文言にし、
  ERROR ログと Discord のエラー通知チャンネル（`discord.error_channel_id`）へ出します。
  存在しない・OS に権限で拒否された、といった想定内のエラーは短い文言だけを返します
- 削除・移動・リネームのツールはありません

### 注意

- 読んだファイルの内容はそのまま LLM へ渡ります。他人が書き込めるディレクトリをホワイトリストに
  入れると、その中に書かれた文章で LLM の振る舞いを誘導される（プロンプトインジェクション）
  おそれがあります。書き込み可能ディレクトリを組み合わせる場合は特に、信頼できる内容の
  ディレクトリだけを指定してください
- 検査してから読み書きするまでの間にリンクを張り替えられる競合（TOCTOU）は防ぎません。
  ホワイトリストのディレクトリへ書き込めるのは信頼できる人だけにしてください
- 書き込みは上書き保存で、競合の検出や版の管理はしません。必要ならバックアップや
  バージョン管理のあるディレクトリを使ってください
- Bot のプロセスの OS 権限で読み書きします。ホワイトリストとは別に、プロセスの権限も
  必要な範囲に絞ってください
