# 観測用ダッシュボード

コアは起動時に、会話履歴・ユーザーメモ・スキル・ログを人が見るための HTTP ダッシュボードを
立ち上げます。有効無効のフラグはありません（起動するなら常に端末が開きます）。
設定は `lilla.yaml` の `dashboard:` で、節そのものを省略すると既定値になります。

```yaml
dashboard:
  host: "0.0.0.0"     # listen するアドレス（既定）
  port: 8765          # listen するポート（既定）
  cookie_secure: true # セッション Cookie に Secure を付けるか（既定）
```

> **セキュリティ上の注意**
>
> このポートは管理画面です。パスワードが未登録のあいだは `POST /api/setup` が管理者
> パスワードを決めるブートストラップで、**一度きりのセットアップトークン**が一致したとき
> だけ受け付けます。トークンは起動時に生成され、bot の起動ログに WARNING で一度だけ出ます
> （`... enter this one-time setup token on the setup screen: <トークン>`）。初期設定画面で
> 新しいパスワードと一緒に貼り付けてください。トークンは画面にも API の応答にも出さないので、
> ポートに届くだけでは管理者パスワードを決められません（ただしログを読める人は決められます）。
> 登録するとトークンは捨てられ、以降の `/api/setup` は 403 で恒久的にブロックされます。
> 未登録のまま再起動すると新しいトークンが出て、古いものは無効になります。
>
> - 既定の `host` は全インターフェース（`0.0.0.0`）です。コンテナ運用を前提にしているため
>   で、**このポートを公開ネットワークへ直接晒さないでください**。前段にアクセス制御
>   （リバースプロキシや Zero Trust など）を置くか、同一ホストからしか使わないなら
>   `host: 127.0.0.1` に絞ってください
> - **起動したら最初に初期パスワードを設定してください**（`/` を開くと初期設定画面が出ます。セットアップトークンは起動ログから取ってください）
> - `cookie_secure: true` は HTTPS 経由を前提にした安全側の既定です。LAN 内で
>   `http://<host>:8765` へ直接アクセスする運用では `false` にしないと、ログインはできても
>   Cookie が送信されずログイン状態を維持できません

## Skills

Skills（`#/skills`）は `!skill` で呼び出すスキルの一覧・追加・編集・削除・有効 / 無効の
切り替えを行う画面です。名前の規則と呼び出し方は [スキル](skills.md) を参照してください。

## Extensions

Extensions（管理メニュー、`#/admin/extensions`）は、ロード済みの拡張の画面管理の設定
（`extension_settings`。設定の本体）と上書き（`extension_overrides`。コードと同梱の既定値は
変えません）を編集する画面です。画面管理の設定・デフォルトのプロンプト・拡張が同梱した定期タスクの
どれかを持つ拡張だけが並び、編集するものの無い節は出しません。

- **設定**: 拡張が `settings_model()` で宣言した設定の本体です（上書きではありません）。保存済みか
  （未保存なら初期値）、項目ごとの値と未設定、検証エラーが分かります。一式を検証してから保存し、
  拡張が次に始める処理から使われます（[画面で管理する拡張の設定](extension-settings.md)）。
  データベースから読めないときは「読めない」と表示し、未保存とは区別します

- **プロンプト**: デフォルト（`ui.locale` → `ja` → `en` の順に選んだもの）・上書きの有無・
  今効いている本文を見て、文字列 1 つで全体を上書きできます。空にして保存すると「この拡張の
  プロンプトを注入しない」という上書きになります。「デフォルトに戻す」は上書きを消すだけで、
  デフォルトの本文はコピーしません。`ui.locale` を変えても上書きは翻訳されません。次の会話から
  効きます（[拡張のデフォルトプロンプトと上書き](extension-prompt.md)）
- **定期タスク**: その拡張が同梱し、ロードされている定期タスクごとに、`schedule`（crontab）と
  定期実行の有効 / 無効だけを上書きできます。crontab は `ui.timezone` で解釈します。無効は
  定期実行を止めるだけで、`!runtask` での手動実行はできます。ツール YAML で `enabled: false` に
  してロードしていないタスクは出てこず、ここから復活させることもできません。コアのタスクや他の
  拡張のタスクも対象外です。保存するとスケジューラへすぐ反映し（実行中のジョブは止めません）、
  反映に失敗したときは失敗と表示して「再反映」でやり直せます
  （[拡張のタスクの上書き](extension-task-override.md)）

保存はリクエスト全体を検証してから 1 回の更新で行い、1 か所でも不正（未知のキー・型の違い・
対象外のタスク・crontab として読めない値）なら何も保存しません。プロンプトだけを保存しても
`tasks` は消えません（逆も同じ）。

画面が使う API（いずれもログイン必須）:

| メソッド・パス | 内容 |
|------|------|
| `GET /api/admin/extensions` | ロード済みの拡張と、編集できるかの目印 |
| `GET /api/admin/extensions/{name}` | プロンプト・タスクのデフォルト・上書き・実効値と、スケジューラに今載っている値。画面管理の設定（`settings`。項目・値・保存済みか・エラー）も含む |
| `PATCH /api/admin/extensions/{name}/overrides` | 上書きの保存。ボディは `{"prompt": 文字列 \| null, "tasks": {ツール名: {"schedule": 文字列 \| null, "enabled": 真偽値 \| null}}}` で、省略したキーは変えず、`null` は上書きを消す。応答の `saved` は保存の成否、`tasks_apply` は反映の結果（`applied` / `scheduler_not_running` / `scheduler_disabled` / `failed`。タスクを変えていなければ `null`） |
| `POST /api/admin/extensions/{name}/tasks/apply` | 保存済みのタスクの上書きの再反映（失敗したら 503） |
| `PUT /api/admin/extensions/{name}/settings` | 画面管理の設定の一式の保存。ボディは `{"values": {項目名: 値}}`。不正なら 400（`errors` に項目ごとの理由）で何も保存しない。設定を宣言していない拡張は 404 |

## Home

Home（`#/`）は一覧を繰り返さず、今の状態だけを出します。開くたびに
`GET /api/dashboard/status`（ログイン必須）を叩き、次の 3 つを表示します。

- 生存確認: ダッシュボード自身が応答していることと、MongoDB への ping の成否。
  LLM の疎通確認を含む full の自己診断（`!selftest full`）は呼びません
- 直近 24 時間の `ERROR` と `WARNING` の件数（ログ保存先の `logs` コレクションを数えます）。
  0 件なら「なし」と出ます。本文・ロガー名・スタックは返しません。ログを MongoDB へ
  保存していない構成では常に「なし」になります

- 直近 24 時間の LLM の呼び出し数と合計トークン数（単価を設定していれば概算コスト）。
  詳しい集計は Usage 画面で見ます

MongoDB に届かないときも画面は落ちず、該当の項目が「応答なし」「取得できません」になります。

## Usage

Usage（`#/usage`）は LLM のトークン使用量を日別・プロバイダー別・入口別に集計する画面です。
記録の設定と中身は [LLM のトークン使用量の記録](llm-usage.md) を参照してください。

`/oauth/{拡張名}` 配下だけは認証ミドルウェアの外に出ます（OAuth の戻り先など、ブラウザが
セッションを持たない状態で叩く公開 GET のため）。前段でアクセス制御を掛ける場合は、この
接頭辞だけをバイパスする構成になります。

パスワードを忘れた場合は、MongoDB の `admin_credentials` コレクションのレコードを手動で
削除すると、初期設定画面から再設定できるようになります。新しいセットアップトークンは、
次に初期設定画面を開いたとき（または次の起動時）にログへ出ます。

拡張からタブや HTTP ルートを足す方法は [ダッシュボードへの差し込み](extension-dashboard.md)
を参照してください。
