# 観測用ダッシュボード

コアは起動時に、会話履歴・ユーザーメモ・スキル・ログを人が見るための HTTP ダッシュボードを
立ち上げます。有効無効のフラグはありません（起動するなら常に端末が開きます）。
設定は `lilla.yaml` の `dashboard:` で、節そのものを省略すると既定値になります。

```yaml
dashboard:
  host: "0.0.0.0"     # listen するアドレス（既定）
  port: 8765          # listen するポート（既定）
  cookie_secure: true # セッション Cookie に Secure を付けるか（既定）
```

> **セキュリティ上の注意**
>
> このポートは管理画面です。パスワードが未登録のあいだは `POST /api/setup` が管理者
> パスワードを決めるブートストラップで、**一度きりのセットアップトークン**が一致したとき
> だけ受け付けます。トークンは起動時に生成され、bot の起動ログに WARNING で一度だけ出ます
> （`... enter this one-time setup token on the setup screen: <トークン>`）。初期設定画面で
> 新しいパスワードと一緒に貼り付けてください。トークンは画面にも API の応答にも出さないので、
> ポートに届くだけでは管理者パスワードを決められません（ただしログを読める人は決められます）。
> 登録するとトークンは捨てられ、以降の `/api/setup` は 403 で恒久的にブロックされます。
> 未登録のまま再起動すると新しいトークンが出て、古いものは無効になります。
>
> - 既定の `host` は全インターフェース（`0.0.0.0`）です。コンテナ運用を前提にしているため
>   で、**このポートを公開ネットワークへ直接晒さないでください**。前段にアクセス制御
>   （リバースプロキシや Zero Trust など）を置くか、同一ホストからしか使わないなら
>   `host: 127.0.0.1` に絞ってください
> - **起動したら最初に初期パスワードを設定してください**（`/` を開くと初期設定画面が出ます。セットアップトークンは起動ログから取ってください）
> - `cookie_secure: true` は HTTPS 経由を前提にした安全側の既定です。LAN 内で
>   `http://<host>:8765` へ直接アクセスする運用では `false` にしないと、ログインはできても
>   Cookie が送信されずログイン状態を維持できません

## Skills

Skills（`#/skills`）は `!skill` で呼び出すスキルの一覧・追加・編集・削除・有効 / 無効と
「LLM から呼べる」（`llm_load_skill` で読み込めるか）の切り替えを行う画面です。名前の規則と呼び出し方は [スキル](skills.md) を参照してください。
本文の欄は [Jinja2 テンプレートの入力欄](#jinja2-テンプレートの入力欄) で、入力中に構文と
展開結果を確かめられます。

## Jinja2 テンプレートの入力欄

Jinja2 のテンプレートとして展開される入力欄（スキルの本文の追加欄・編集欄と、設定画面の
拡張のプロンプトの上書き欄。後者は下記の [プロンプトの上書きの入力部品](#プロンプトの上書きの入力部品) の中で使う）には、
共通の入力部品を使います。

- 「Jinja2 テンプレート」の表示と、使える変数の一覧を出します。変数をクリックすると、カーソルの
  位置へ `{{ 名前 }}` を差し込みます。一覧には共通の `current_hour` が必ず入り、拡張のプロンプトでは
  `settings.名前`（秘匿値の項目は除く）も入ります
- 入力が止まってから少しして（約 0.4 秒）、サーバーで保存時と同じ試しの展開を行い、結果を出します。
  展開できなければ理由（構文エラーは行番号つき）を、展開できれば「展開後のプレビュー」に展開した本文を
  出します。`{# … #}` で展開すると消える部分は、行番号と中身をプレビューの下に並べます
- 拡張のプロンプトで設定を読めないときは、保存時と同じく構文だけを確かめ、その旨を表示します
- 構文の色分けはしません。プレビューは確認用で、保存の操作と保存時の検査はこれまでどおりです

展開はブラウザでは行わず、次の API を呼びます（ログイン必須。本文は保存しません）。

| メソッド・パス | 内容 |
|------|------|
| `POST /api/admin/prompt-preview` | ボディは `{"text": 本文, "target": {"type": "skill"}}` か `{"text": 本文, "target": {"type": "extension", "name": 拡張名}}`。スキルは保存時と同じく前後の空白を除いてから `current_hour` だけで、拡張のプロンプトは今の設定（秘匿値を除く）でも展開します。成功は 200 で `{"rendered": 展開した本文 \| null, "comments": [{"line", "text"}], "settings_unavailable": 真偽値}`（設定を読めず展開を飛ばしたときは `rendered` が `null`）。展開できなければ 400 で `{"error": 理由}`。未ロードの拡張・デフォルトのプロンプトを持たない拡張は 404 |

### 部品を使う（ダッシュボードの開発者向け）

部品は `src/lilla_core/dashboard/jinja-editor.js` が `Alpine.data('jinjaEditor', …)` として登録し、
見た目は `index.html` の `<template id="jinja-editor-tpl">` にあります。空の要素に `x-data` で付け、
本文は `x-modelable="text"` と `x-model` で呼び出し側の値と結びます。

```html
<div x-data="jinjaEditor({
       target: () => ({ type: 'extension', name: exts.selected }),
       variables: () => ['settings.day_rollover'],
       fetch: (u, o) => authedFetch(u, o),
       rows: 12,
     })"
     x-modelable="text" x-model="skills.newPrompt"></div>
```

| 引数 | 内容 |
|------|------|
| `target` | プレビューで使う変数セット（API の `target` と同じ形）。値か、値を返す関数（選択の切り替えに追従させるとき） |
| `variables` | 一覧に足す変数名（`current_hour` は部品が先頭に足す）。値か関数 |
| `fetch` | API を呼ぶ関数。ダッシュボードの `authedFetch` を渡すと、セッション切れのときにログイン画面へ戻る |
| `rows` / `placeholder` | 入力欄の見た目 |

状態はインスタンスごとに持つため、複数並べても本文・プレビューは混ざりません。要素を外すと
（`x-if` で消すなど）待機中のプレビューを止めます。一覧の各行で使う編集欄のように、同じ値を
複数の行が見る場所では `x-if` で編集中の行にだけ部品を置いてください（置いた数だけプレビューを
問い合わせるため）。

## プロンプトの上書きの入力部品

デフォルトのプロンプトに「追加するか」「置き換えるか」を選んで本文を書く入力欄には、共通の部品を
使います。今これを使うのは 設定画面のプロンプトの欄だけです。

- 「デフォルトプロンプトに追加」と「デフォルトプロンプトを置き換える」のラジオで、モードを選びます
- 追加モードのときだけ、入力欄の上にデフォルトの本文を言語つきの読み取り専用で出します
  （選択・手動でのコピーができます）。置き換えモードでは出しません
- 入力欄は [Jinja2 テンプレートの入力欄](#jinja2-テンプレートの入力欄) で、入力した本文だけを
  そのまま渡します（プレビューと保存時の検査は入力した本文だけが対象で、モードは関係しません）
- モードを切り替えても入力した本文は消えず、デフォルトを自動で差し込むこともしません。
  専用のコピーボタンはありません

### 部品を使う（ダッシュボードの開発者向け）

部品は `src/lilla_core/dashboard/prompt-override-editor.js` が `Alpine.data('promptOverrideEditor', …)`
として登録し、見た目は `index.html` の `<template id="prompt-override-editor-tpl">` にあります。
中で `jinjaEditor` を使うため、使う画面では `jinja-editor.js` とこのファイルの両方を `app.js` より前に
`<script>` で読み込みます（どちらも `alpine:init` の中で登録します）。空の要素に `x-data` で付け、
値 `{mode: 'append' | 'replace', text}` を `x-modelable="value"` と `x-model` で呼び出し側の値と結びます。

```html
<div x-data="promptOverrideEditor({
       defaultText: () => exts.detail.prompt.default,
       defaultLocale: () => exts.detail.prompt.default_locale,
       target: () => ({ type: 'extension', name: exts.selected }),
       variables: () => ['settings.day_rollover'],
       fetch: (u, o) => authedFetch(u, o),
       rows: 12,
     })"
     x-modelable="value" x-model="exts.promptDraft"></div>
```

| 引数 | 内容 |
|------|------|
| `defaultText` / `defaultLocale` | 追加モードのときに見せるデフォルトの本文と言語。値か、値を返す関数 |
| `target` / `variables` / `fetch` / `rows` / `placeholder` | そのまま `jinjaEditor` へ渡す（意味は上の表と同じ）。値か関数 |

呼び出し側の値は常に `{mode, text}` のオブジェクトにしてください（初期値は `{mode: 'append', text: ''}`）。
拡張名などは部品に持たせず、引数で渡します。状態（ラジオの組を含む）はインスタンスごとに持つため、
複数並べてもモード・本文・プレビューは混ざりません。要素を外したときの後始末は中の `jinjaEditor` が
行います。バッジ・説明文・警告・保存やリセットのボタンは部品に含めず、呼び出し側の画面に置きます。

## 画面の構成

中央のナビは、ふだん使う画面（ホーム / 会話 / メモ / スキル / 使用量）と、拡張が足した画面
（`dashboard_page()`。例: ノート）です。右上のメニューにはログ（`#/admin/logs`）・設定
（`#/settings`）・ログアウトが並びます。ダッシュボードの文言は日本語の直書きです。

## 設定

設定（右上のメニュー、`#/settings`）は左のメニューで次の 3 つを切り替えます。

| メニュー | ハッシュ | 内容 |
|------|------|------|
| 全般 | `#/settings` | コアの今の動作の要約（表示言語・タイムゾーン・LLM のプロバイダーと今使っているもの・ツールの無効化・内部スケジューラ・ダッシュボードと共有 HTTP サーバーの listen 先・読み込んだ拡張）。**読み取り専用**で、値の正本は `lilla.yaml` です（画面から変える経路は持たず、二重管理にしません）。秘匿情報（`.env` の値）とプロバイダーの URL は出しません |
| 標準機能（今は ノートと長期記憶） | `#/settings/{name}` | 標準機能の拡張（`BUILTIN_EXTENSION_MODULES`）の設定。拡張機能の一覧には入れず、全般と並べます |
| 拡張機能 | `#/settings/extensions` | それ以外に読み込んだ拡張の一覧。設定する項目の無い拡張も並び、公式拡張パックのものには「公式」の印が付きます。選ぶと `#/settings/extensions/{name}` でその拡張の設定を開きます |

一覧と見出しには拡張の表示名（`Extension.display_name()`。未指定なら `name`）を使います。
画面を持つ拡張は、設定から「〈表示名〉を開く」で画面へ、画面の上の「⚙ 設定」で設定へ移れます。
以前の `#/admin/extensions` は使えません（別名は置いていないので、ブックマークは張り直してください）。

各拡張の設定の画面では、画面管理の設定（`extension_settings`。設定の本体）と上書き
（`extension_overrides`。コードと同梱の既定値は変えません）を編集します。編集するものの無い節は出しません。

- **設定**: 拡張が `settings_model()` で宣言した設定の本体です（上書きではありません）。保存済みか
  （未保存なら初期値）、項目ごとの値と未設定、検証エラーが分かります。一式を検証してから保存し、
  拡張が次に始める処理から使われます（[画面で管理する拡張の設定](extension-settings.md)）。
  データベースから読めないときは「読めない」と表示し、未保存とは区別します

- **プロンプト**: 「デフォルトプロンプトに追加」（デフォルトの後ろに書き足す）か
  「デフォルトプロンプトを置き換える」（入力した本文だけを使う）を選んで上書きできます。
  欄は [プロンプトの上書きの入力部品](#プロンプトの上書きの入力部品) で、追加モードのときだけ
  デフォルト（`ui.locale` → `ja` → `en` の順に選んだもの）を言語つきで出します。編集欄には保存済みの
  モードと本文が入り（上書きが無ければ追加モード・空の本文）、デフォルトと合わせた全文は入りません。
  追加モードのデフォルト部分は、拡張のデフォルトの更新や `ui.locale` の変更に追従します（入力した
  本文は翻訳されません）。置き換えモードで空にして保存すると「この拡張のプロンプトを注入しない」
  という上書きになります。「デフォルトに戻す」は上書きを消し、編集欄も追加モード・空の本文に戻します。
  保存済みの値が今の形式に合わない（以前の文字列 1 つの形式など）ときは警告を出してデフォルトを
  使うので、保存し直すか「デフォルトに戻す」を押してください。次の会話から効きます
  （[拡張のデフォルトプロンプトと上書き](extension-prompt.md)）
- **定期タスク**: その拡張が同梱し、ロードされている定期タスクごとに、`schedule`（crontab）と
  定期実行の有効 / 無効だけを上書きできます。crontab は `ui.timezone` で解釈します。無効は
  定期実行を止めるだけで、`!runtask` での手動実行はできます。ツール YAML で `enabled: false` に
  してロードしていないタスクは出てこず、ここから復活させることもできません。コアのタスクや他の
  拡張のタスクも対象外です。保存するとスケジューラへすぐ反映し（実行中のジョブは止めません）、
  反映に失敗したときは失敗と表示して「再反映」でやり直せます
  （[拡張のタスクの上書き](extension-task-override.md)）

保存はリクエスト全体を検証してから 1 回の更新で行い、1 か所でも不正（未知のキー・型の違い・
対象外のタスク・crontab として読めない値・プロンプトの未知のモード・入力した本文を展開できない）
なら何も保存しません。プロンプトだけを保存しても
`tasks` は消えません（逆も同じ）。

画面が使う API（いずれもログイン必須）:

| メソッド・パス | 内容 |
|------|------|
| `GET /api/admin/settings/general` | 全般の内容（読み取り専用。秘匿情報とプロバイダーの URL は含まない） |
| `GET /api/admin/extensions` | ロード済みのすべての拡張。`name` / `display_name` / `kind`（`builtin` / `official` / `external`）/ 編集できるか（`editable`）/ 設定の画面のハッシュ（`settings_hash`）/ 拡張の画面のハッシュ（`page_hash`。画面が無ければ `null`）など |
| `GET /api/admin/extensions/{name}` | プロンプト・タスクのデフォルト・上書き・実効値と、スケジューラに今載っている値。プロンプトは `default` / `default_locale` / `overridden` / `mode` / `text`（上書きがあるときだけ値を持つ）/ `invalid` / `effective`（デフォルトと入力した本文を展開前のまま空行でつないだ表示用の本文）/ `template_variables`。画面管理の設定（`settings`。項目・値・保存済みか・エラー）も含む |
| `PATCH /api/admin/extensions/{name}/overrides` | 上書きの保存。ボディは `{"prompt": {"mode": "append" \| "replace", "text": 文字列} \| null, "tasks": {ツール名: {"schedule": 文字列 \| null, "enabled": 真偽値 \| null}}}` で、省略したキーは変えず、`null` は上書きを消す。応答の `saved` は保存の成否、`tasks_apply` は反映の結果（`applied` / `scheduler_not_running` / `scheduler_disabled` / `failed`。タスクを変えていなければ `null`）。`prompt` は `mode` と `text` の両方が必要で、ほかのキーは受け付けない（以前の文字列 1 つの形式も 400）。構文の確認と試しの展開は `text` だけが対象 |
| `POST /api/admin/extensions/{name}/tasks/apply` | 保存済みのタスクの上書きの再反映（失敗したら 503） |
| `POST /api/admin/prompt-preview` | 上書きの本文を試しに展開した結果（[Jinja2 テンプレートの入力欄](#jinja2-テンプレートの入力欄)） |
| `PUT /api/admin/extensions/{name}/settings` | 画面管理の設定の一式の保存。ボディは `{"values": {項目名: 値}}`。不正なら 400（`errors` に項目ごとの理由）で何も保存しない。設定を宣言していない拡張は 404 |

## Home

Home（`#/`）は一覧を繰り返さず、今の状態だけを出します。開くたびに
`GET /api/dashboard/status`（ログイン必須）を叩き、次の 3 つを表示します。

- 生存確認: ダッシュボード自身が応答していることと、MongoDB への ping の成否。
  LLM の疎通確認を含む full の自己診断（`!selftest full`）は呼びません
- 直近 24 時間の `ERROR` と `WARNING` の件数（ログ保存先の `logs` コレクションを数えます）。
  0 件なら「なし」と出ます。本文・ロガー名・スタックは返しません。ログを MongoDB へ
  保存していない構成では常に「なし」になります

- 直近 24 時間の LLM の呼び出し数と合計トークン数（単価を設定していれば概算コスト）。
  詳しい集計は Usage 画面で見ます

MongoDB に届かないときも画面は落ちず、該当の項目が「応答なし」「取得できません」になります。

## Usage

Usage（`#/usage`）は LLM のトークン使用量を日別・プロバイダー別・入口別に集計する画面です。
記録の設定と中身は [LLM のトークン使用量の記録](llm-usage.md) を参照してください。

`/oauth/{拡張名}` 配下だけは認証ミドルウェアの外に出ます（OAuth の戻り先など、ブラウザが
セッションを持たない状態で叩く公開 GET のため）。前段でアクセス制御を掛ける場合は、この
接頭辞だけをバイパスする構成になります。

パスワードを忘れた場合は、MongoDB の `admin_credentials` コレクションのレコードを手動で
削除すると、初期設定画面から再設定できるようになります。新しいセットアップトークンは、
次に初期設定画面を開いたとき（または次の起動時）にログへ出ます。

拡張からタブや HTTP ルートを足す方法は [ダッシュボードへの差し込み](extension-dashboard.md)
を参照してください。
