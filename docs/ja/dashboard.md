# 観測用ダッシュボード

コアは起動時に、会話履歴・ユーザーメモ・ログを人が見るための HTTP ダッシュボードを
立ち上げます。有効無効のフラグはありません（起動するなら常に端末が開きます）。
設定は `lilla.yaml` の `dashboard:` で、節そのものを省略すると既定値になります。

```yaml
dashboard:
  host: "0.0.0.0"     # listen するアドレス（既定）
  port: 8765          # listen するポート（既定）
  cookie_secure: true # セッション Cookie に Secure を付けるか（既定）
```

> **セキュリティ上の注意**
>
> このポートは管理画面です。パスワードが未登録のあいだは `POST /api/setup` が管理者
> パスワードを決めるブートストラップで、**一度きりのセットアップトークン**が一致したとき
> だけ受け付けます。トークンは起動時に生成され、bot の起動ログに WARNING で一度だけ出ます
> （`... enter this one-time setup token on the setup screen: <トークン>`）。初期設定画面で
> 新しいパスワードと一緒に貼り付けてください。トークンは画面にも API の応答にも出さないので、
> ポートに届くだけでは管理者パスワードを決められません（ただしログを読める人は決められます）。
> 登録するとトークンは捨てられ、以降の `/api/setup` は 403 で恒久的にブロックされます。
> 未登録のまま再起動すると新しいトークンが出て、古いものは無効になります。
>
> - 既定の `host` は全インターフェース（`0.0.0.0`）です。コンテナ運用を前提にしているため
>   で、**このポートを公開ネットワークへ直接晒さないでください**。前段にアクセス制御
>   （リバースプロキシや Zero Trust など）を置くか、同一ホストからしか使わないなら
>   `host: 127.0.0.1` に絞ってください
> - **起動したら最初に初期パスワードを設定してください**（`/` を開くと初期設定画面が出ます。セットアップトークンは起動ログから取ってください）
> - `cookie_secure: true` は HTTPS 経由を前提にした安全側の既定です。LAN 内で
>   `http://<host>:8765` へ直接アクセスする運用では `false` にしないと、ログインはできても
>   Cookie が送信されずログイン状態を維持できません

`/oauth/{拡張名}` 配下だけは認証ミドルウェアの外に出ます（OAuth の戻り先など、ブラウザが
セッションを持たない状態で叩く公開 GET のため）。前段でアクセス制御を掛ける場合は、この
接頭辞だけをバイパスする構成になります。

パスワードを忘れた場合は、MongoDB の `admin_credentials` コレクションのレコードを手動で
削除すると、初期設定画面から再設定できるようになります。新しいセットアップトークンは、
次に初期設定画面を開いたとき（または次の起動時）にログへ出ます。

拡張からタブや HTTP ルートを足す方法は [ダッシュボードへの差し込み](extension-dashboard.md)
を参照してください。
