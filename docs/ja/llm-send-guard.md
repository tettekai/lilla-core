# LLM 送信前の拒否リスト

プロンプトやツールの作りで個人情報を渡さないようにしていても、会話履歴やツール結果の
文字列に本名やメールアドレスが混ざることがあります。`llm.send_blocklist_path` を設定すると、
LLM へ送る直前に、リクエストボディをホストの拒否リストで調べます。一致した回はモデルへ
送りません。

これは送信直前の最後の網です。言い換え・略称・画像の中の文字は検出しません。

## 設定

```yaml
llm:
  send_blocklist_path: /run/secrets/lilla-blocklist.json
```

- 省略した場合（既定）は検査しません。従来どおり送ります。
- 値は **絶対パスだけ** を受け付けます。相対パス・`file:` / `dir:` 接頭・`${config_root}` の
  展開は起動時にエラーになります。リストは `CONFIG_ROOT` の外に置く前提です。
- リストの中身は `lilla.yaml` に書きません。

リストファイルは JSON の文字列配列です（コメントは書けません）。

```json
["山田太郎", "Yamada Taro", "090-0000-0000"]
```

## 調べる範囲

- 対象は `chat_to_llm` / `chat_to_llm_with_tools` / `chat_to_llm_responses` です。会話ループを
  通らない直接の呼び出しも同じように調べます。
- 調べるのは、送信する JSON ボディに含まれる文字列すべてです（辞書のキーも含みます）。
  システムプロンプト・メッセージ・ツール結果・ツール定義・プロバイダーの `extra_params`・
  Responses API の `input` / `instructions` のどこにあっても対象になります。
- `Authorization` などのヘッダーは調べません。API キーが検査やログに載ることはありません。
- 画像の data URL（`data:...;base64,...`）は対象外です。
- 比較の前に、両方を NFKC で正規化して大文字小文字を無視します。リストの語は部分一致です。
  短い語は誤検知を招くため、リストに入れないでください。
- 検査が有効なあいだは、リストとは別にメールアドレスの形も常に調べます（空の配列でも同じ）。

## 一致したとき・リストが使えないとき

- その回は送信しません。一致箇所を伏せて送り直すこともしません。
- Discord の通常会話では、エラー通知チャンネル（`discord.error_channel_id`）に
  「個人情報が含まれている可能性があるため、LLM へ送信しませんでした」とだけ通知します。
  一致した語は含みません。
- ログは送信を止めた事実と種類（リストの語かメールアドレスの形か）だけを残します。
  一致した語・リクエスト本文・ヘッダーは出しません。例外メッセージにも載せません。
- リストは起動時に一度だけ読み、プロセスのメモリに持ちます。ファイルを書き換えたら
  再起動してください。
- パスを指定したのに、ファイルが読めない・JSON でない・文字列配列でない・空文字を含む
  場合は、起動は止めずに ERROR ログを出し、以後の LLM 送信をすべて止めます。

## 対象外

- 一度送ってしまった内容の取り消し
- 言い換え・略称・画像の中の文字
- ツールからリストファイルを読めなくすること。ホスト側のマウントとツールの許可範囲で
  行ってください
