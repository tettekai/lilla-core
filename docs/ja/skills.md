# スキル

スキルは、使い回す指示プロンプトに名前を付けて保存しておき、`!skill <スキル名>` で
呼び出す機能です。呼び出すと、そのターンの **最新の user メッセージ** としてプロンプトが
展開され、通常の会話と同じ流れで LLM に渡ります（システムプロンプトには入りません）。

組み込みツール `llm_load_skill` を有効にすると、LLM が会話の流れからスキルの説明を見て
必要なものを自分で読み込むこともできます（[LLM が自分でスキルを読み込む](#llm-が自分でスキルを読み込む)）。

## 登録する

スキルは観測用ダッシュボード（[観測用ダッシュボード](dashboard.md)）の **Skills** 画面で
管理します。一覧・追加・編集・削除・有効 / 無効の切り替えができます。

| 項目 | 内容 |
|------|------|
| 名前 | 呼び出しに使う名前（必須） |
| 説明 | 一覧に出す説明（任意。ダッシュボードの一覧と `!skill` の一覧に表示される。`llm_load_skill` を有効にした会話ではシステムプロンプトのスキル一覧にも載り、LLM が読み込むかを判断する材料になる） |
| 本文 | 展開するプロンプト（必須） |
| 有効 | 無効にしたスキルは呼び出せません（追加直後は有効） |

保存先は MongoDB の `skills` コレクションです（`name` にユニークインデックス）。

### 名前の規則

- 使える文字は半角英数字・アンダースコア（`_`）・ハイフン（`-`）のみで、最大 64 文字です。
  空白は含められません（コマンドの引数を空白で区切るため）
- 大文字小文字は区別しません。保存時も呼び出し時も小文字に正規化して照合します。
  `Review` と `review` を別々に登録することはできず、`!skill Review` は `review` を呼びます
- 規則に合わない名前や、既にある名前と重なる名前は、追加・編集の時点でエラーになります

## 呼び出す

```
!skill <スキル名> [追加指示]
```

スキルの本文は、ユーザー自身の発言ではなく **システムからの動作指示** として LLM に読まれる
よう、開始行・前置き文・終了行のラッパーで囲んで展開します。スキル名の後ろに書いた文字列
（最初の空白以降）は追加指示として、前後の空白を除いたうえで、ラッパーの後ろに `追加指示: `
のラベル付きで続けます（複数行なら 1 行目にだけラベルが付きます）。たとえば本文が
「次の文章を校正して」のスキル `proofread` を `!skill proofread 今日は良い天気でした。` で
呼ぶと、LLM には次の user メッセージが渡ります。

```text
[システム指示: スキル「proofread」]
以下はユーザーの発言ではなく、システムからの動作指示です。この指示に従って応答してください。

次の文章を校正して
[/システム指示]

追加指示: 今日は良い天気でした。
```

追加指示が無い（空・空白だけの）ときは、`追加指示:` の行を付けずラッパーだけを渡します。

```text
[システム指示: スキル「proofread」]
以下はユーザーの発言ではなく、システムからの動作指示です。この指示に従って応答してください。

次の文章を校正して
[/システム指示]
```

ラッパーの文言とラベルは `ui.locale` に合わせて切り替わります（`en` なら
`[System instruction: skill "proofread"]` / `[/System instruction]` /
`Additional instructions: `）。

- 展開した内容は、そのまま会話履歴に user メッセージとして残ります。スキルを後から
  編集・削除しても、過去の履歴は保存した時点の内容のまま読まれます
- 以前の形式（`---SKILL: <スキル名>---` 〜 `---END_SKILL---` の区切りマーカー）で保存済みの
  履歴は移行せず、そのまま残ります
- 返答の送り方（入力中表示・分割送信・返答の履歴保存）は通常の会話と同じです。同じ
  チャンネルで返答中の会話があれば、通常の会話と同じくそれを打ち切ってから始めます
- メンションなしで呼び出せます（他の `!` コマンドと同じ）
- 存在しない・無効なスキルを指定すると、LLM を呼ばずに元のチャンネルへエラーを返します
- オーナー以外からの `!skill` は、他のコマンドと同じく承認フローの対象です
  （承認チャンネルで承認されると実行されます）

### スキルの一覧を見る

スキル名を付けずに `!skill` だけを送ると（空白だけの引数も同じ）、LLM を呼ばずに、
呼び出せるスキルの一覧を同じチャンネルへ返します。

```text
利用できるスキル:
- `proofread`: 文章を校正する
- `review`
呼び出し方: `!skill <スキル名> [追加指示]`
```

- 載るのは **有効なスキルだけ** で、スキル名の昇順に並びます。無効なスキルは呼び出せない
  ため載りません
- 説明があれば `名前: 説明`、無ければ名前だけを表示します。説明の改行は空白に置き換えて
  1 行にします（長い説明も切り詰めません）
- 有効なスキルが 1 件も無いときは、一覧の代わりに「利用できるスキルはありません」と、
  ダッシュボードの Skills 画面から登録できる旨を返します
- 一覧が Discord の 1 メッセージに収まらないときは、行の区切りで複数のメッセージに分けて
  続けて送ります
- オーナー以外からの一覧表示も承認フローの対象で、承認されると元のチャンネルへ一覧を返します

## LLM が自分でスキルを読み込む

組み込みツール `llm_load_skill` を有効にすると、LLM が有効なスキルの一覧を見て、必要と
判断したときに名前を指定して本文を読み込めます。

### 有効にする

他の組み込みツールと同じく opt-in です。`${CONFIG_ROOT}/tools/llm_load_skill.yaml` を置き、
`tools.sets`（`main` など）に含めた場合だけ LLM に渡ります。

```yaml
type: llm_load_skill
# 以下はシステムプロンプトのスキル一覧の上限（省略時は既定値）
max_skills: 50              # 一覧に載せる件数
max_description_chars: 200  # 1 件あたりの説明の最大文字数
max_list_chars: 4000        # 一覧の各行の合計文字数
```

```yaml
# lilla.yaml
tools:
  sets:
    main:
      - llm_load_skill
```

上限はいずれも正の整数で、0 以下や数値でない値を書くと起動時にエラーになります。

### ツールの引数と結果

| 引数 | 内容 |
|------|------|
| `name` | 読み込むスキル名（必須）。`!skill` と同じ規則で検証し、大文字小文字は区別しない |
| `reason` | 読み込む理由や、読み込んだ後に行う予定の内容（任意）。結果には使わず、ツール呼び出しの引数として残るだけ |

成功すると、`!skill` と同じ「システムからの動作指示」のラッパー（追加指示なし）で囲んだ本文が
ツール結果として返ります。名前が規則に合わない・存在しない・無効なスキルはエラーになります
（存在しない場合と無効な場合はエラー文言が異なります）。

結果はキャッシュせず、呼び出しのたびに `skills` コレクションから読みます。ダッシュボードで
スキルを編集・有効化・無効化すると、次の呼び出しから反映されます。

### システムプロンプトに載る一覧

`llm_load_skill` がその会話で LLM に渡されるときだけ、有効なスキルの **名前と説明** の一覧を
システムプロンプトへ足します（本文は入りません）。`tools.sets` に含まれていない、
`!disable_tools` 中、ツールなしで LLM を呼ぶ、のいずれかの場合は足しません。

```text
## 利用できるスキル
以下のスキルは `llm_load_skill` ツールに名前を指定すると本文を読み込めます。一覧の名前と説明を見て、必要と判断したときだけ読み込んでください。
- proofread: 文章を校正する
- review
```

- スキル名の昇順に並びます。説明が無ければ名前だけで、説明の改行は空白に置き換えます
- 説明が `max_description_chars` を超えると切り詰めて末尾に `…` を付けます
- 先頭から行を足していき、件数（`max_skills`）か各行の合計文字数（`max_list_chars`。見出しと
  説明文は数えない）のどちらかの上限に達したら以降は載せません。省略した件数があれば、
  末尾に「ほか N 件は一覧に載せていない。名前が分かれば読み込める」旨の 1 行が付きます。
  一覧に載らないスキルも、有効であれば `llm_load_skill` で読み込めます
- 有効なスキルが 1 件も無ければ節ごと足しません
- 一覧もキャッシュせず、システムプロンプトを組み立てるたびに取得します

スキルの説明は LLM が読み込むかどうかを決める判断材料になるため、何をするスキルかが
分かるように書いてください。
