# LLM 応答の先頭 prefix の除去

LLM は応答の先頭に、自発的にタイムスタンプ風の prefix を付けることがあります
（例: `[19:14] そうなんだ…`）。会話履歴のユーザー発言にシステムが時刻を付けているため、
それを真似てしまうことがあり、プロンプトでの抑制は完全ではありません。

Discord へ返信するとき、lilla-core は応答を `---SPLIT---`・空行・タイムスタンプの境界で
複数のメッセージ（ブロック）に分けて送ります。`llm.response_prefix_strip_patterns` に
書いた正規表現は、分割した **各ブロックの先頭** から順番に除去します。

## 設定

```yaml
llm:
  response_prefix_strip_patterns:
    - '\[(?:Jan|Feb|Mar|Apr|May|Jun|Jul|Aug|Sep|Oct|Nov|Dec) \d{1,2} \d{2}:\d{2}\]\s*'
    - '\[\d{1,2}:\d{2}\]\s*'
```

- 省略した場合（キーだけ書いて値が空の場合も）は上の 2 つを既定として使います。
  システムが履歴に付ける `[Apr 28 11:22] ` 形式と、単純な `[HH:MM]` 形式です。
- 空リスト（`[]`）を書くと何も除去しません。
- 既定に足したいときは、既定の 2 つも含めて書きます（書いたリストで既定を置き換えます）。
- 不正な正規表現を書くと起動時にエラーになります。

## 除去の規則

- 各パターンはブロックの先頭にだけマッチします（`re.match` 相当）。パターンに `^` を
  書く必要はありません。文中・末尾の一致は残します。
- パターンは書いた順に 1 回ずつ適用します。前のパターンで除去したあとの先頭（前後の空白は
  詰めたもの）に、次のパターンを当てます。
- 一致した部分は空文字に置き換えます（除去のみ。置換文字列は指定できません）。
- 除去した結果が空、または意味のある文字を含まないブロックは送りません。
- 対象は Discord の通常会話の返信だけです。会話履歴には、除去したあとのブロックが
  送ったとおりに残ります。定期タスクの通知など、応答を分割しない経路には適用しません。

## YAML での書き方

YAML のシングルクォート（`'...'`）の中ではバックスラッシュがエスケープされないため、
正規表現の `\` は 1 つで書きます（上の例のとおり）。ダブルクォート（`"..."`）で書く場合は
`\\` と 2 つ重ねる必要があります。
